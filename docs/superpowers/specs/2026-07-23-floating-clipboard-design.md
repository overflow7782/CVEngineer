# 浮贴：Windows 悬浮剪贴板便签设计文档

## 1. 背景

现有剪贴板管理器通常以历史面板、搜索工具或知识库形式存在，操作入口较深，常驻界面也偏重。本产品定位为一个类似桌宠的轻量悬浮便签：始终位于工作区上层，以最小面积展示当前剪贴板内容，需要时进入历史列表，并可查看单条详情。

本文以已确认的玻璃拟态原型图为视觉基准，并补充原型中未覆盖的收缩预览。产品明确划分为收缩预览、历史列表、单条详情三个状态。历史列表直接读取 Windows 剪贴板历史，最多展示系统返回的前 25 条记录；应用不建立第二套历史库。

## 2. 目标

- 用户不切换应用即可查阅当前剪贴板内容。
- 收缩预览仅展示当前记录的缩略内容和格式解析结果。
- 历史列表最多显示 Windows 返回的前 25 条记录，并支持快速重新复制。
- 单条详情在历史列表内展开一条选中记录，显示内容、元数据和操作区。
- 支持文本、图片、文件、链接和代码内容。
- 首期对 JSON、Markdown 做明确的格式解析，其他代码按通用代码样式展示。
- 窗口支持窗口级始终置顶，保持玻璃质感和清晰的信息层级。
- Release 版本收缩且空闲时，私有工作集目标不超过 50 MB。
- 所有剪贴板数据只在本机处理，不依赖账号和云服务。
- 应用退出时释放全部历史投影，重启后重新读取 Windows 当前历史，不保存历史内容。

## 3. 非目标

- 不提供账号、云同步和跨设备历史。
- 不建设收藏夹、标签页、知识库或团队协作能力。
- 首期不识别所有编程语言，不引入完整 IDE 级语法分析器。
- 不抓取链接网页内容，不因复制链接发起网络请求。
- 不索引文件内容；文件路径列表和基础元数据仅在进程内按需读取和处理。
- 不替代或复制 Windows 系统剪贴板历史，不保存历史内容到应用目录或数据库。

## 4. 产品范围

### 4.1 首期包含

- 读取 Windows 系统剪贴板历史并监听系统历史变化。
- 收缩预览、历史列表、单条详情三个状态及其切换。
- 历史列表最多展示 Windows 返回的前 25 条记录。
- 单条详情的展开、收起和重新复制。
- 文本、图片、文件、链接、JSON、Markdown、通用代码的缩略展示。
- 复制、纯文本复制、删除、清空 Windows 历史。
- 暂停监听、窗口级始终置顶和基础设置。
- Windows 11 玻璃背景；Windows 10 使用低透明度的兼容背景。
- 按显示器 DPI 自动缩放。

### 4.2 后续候选

- 全局快捷键。
- 指定应用排除列表。
- OCR、链接预览、更多代码语言高亮。
- ARM64 安装包。

## 5. 交互与视觉设计

### 5.1 视觉原则

- 延续原型中的冷白玻璃背景、细描边、轻阴影和浅青绿色强调色。
- 信息通过图标、类型标签、缩略内容和元数据表达，避免大面积卡片嵌套。
- 窗口圆角为 8 px；按钮以 28-32 px 方形图标按钮为主。
- 正文优先使用 Segoe UI Variable 和系统中文字体；代码使用 Cascadia Mono。
- 文本始终保持可读对比度，玻璃透明度不随桌面背景无限变化。
- 动画只用于状态切换，时长控制在 120-180 ms，不使用持续动画。

### 5.2 窗口状态与切换

#### 收缩预览

- 参考尺寸：宽 340 px，高 118-146 px，按 DPI 等比缩放。
- 由标题栏和“当前记录摘要”两部分组成。
- 标题栏保留产品标识、监听状态、置顶、暂停、设置、展开和关闭操作。
- 当前记录摘要必须包含：
  - 内容类型图标；
  - 类型标签，例如 `JSON`、`Markdown`、`链接`、`图片`、`文件`、`文本`；
  - 1-3 行缩略内容；
  - 与类型对应的解析信息；
  - 复制按钮。
- 点击摘要主体或展开按钮进入历史列表；点击复制图标只执行复制，不改变窗口状态。
- 收缩预览永远只显示当前记录，不轮播历史，不显示历史列表。
- 没有剪贴板内容时显示“等待复制内容”，不显示空白卡片。

各类型的收缩预览摘要如下：

| 类型 | 缩略展示 | 格式解析信息 |
| --- | --- | --- |
| 文本 | 最多 3 行纯文本，超出省略 | 字符数、行数 |
| JSON | 最多 4 行等宽代码，轻量语法着色 | JSON、行数、字符数、解析状态 |
| Markdown | 标题或首段，保留一级列表结构 | Markdown、标题数、列表项数 |
| 通用代码 | 最多 4 行等宽文本 | 代码、行数、字符数 |
| 链接 | 主机名、路径摘要；有锚文本时优先显示锚文本 | HTTPS/HTTP、域名 |
| 图片 | 64 x 48 px 等比例缩略图 | 像素尺寸、编码格式、文件大小 |
| 文件 | 第一个文件名和文件图标；多文件显示 `+N` | 文件类型、文件数量、总大小（可读取时） |

#### 历史列表

- 参考尺寸：宽 380 px，高度 520-680 px；不得超过当前显示器工作区高度的 72%。
- 标题栏下方为可滚动历史列表，最多 25 条。
- 所有记录均保持紧凑单行或双行摘要；当前记录使用当前态样式标识，但不自动展开详情。
- 点击任一记录主体进入单条详情；点击快速复制按钮只执行复制，不改变窗口状态。
- 历史列表独立滚动，标题栏和底部状态栏保持固定。
- 底部显示 `N / 25 条记录` 和清空按钮。
- 新记录到达时插入列表顶部并成为当前记录；用户正在浏览非顶部位置时不强制滚动，只显示轻量“有新内容”提示。

#### 单条详情

- 沿用历史列表的窗口尺寸、标题栏、底部状态栏和滚动容器。
- 选中记录在列表原位置展开为详情，其余记录保持紧凑摘要。
- 同一时间只允许一条记录展开。点击另一条记录时，原记录收起，新记录原位展开。
- 点击详情收起按钮返回历史列表，并保留当前滚动位置。
- 点击标题栏收缩按钮直接返回收缩预览。

状态切换规则如下：

| 当前状态 | 用户操作 | 目标状态 |
| --- | --- | --- |
| 启动 | 应用完成首次历史读取 | 收缩预览 |
| 收缩预览 | 点击摘要主体或展开按钮 | 历史列表 |
| 历史列表 | 点击记录主体 | 单条详情 |
| 单条详情 | 点击当前详情的收起按钮 | 历史列表 |
| 单条详情 | 点击其他记录主体 | 单条详情，切换选中记录 |
| 历史列表或单条详情 | 点击标题栏收缩按钮 | 收缩预览 |
| 任意状态 | 点击关闭按钮 | 退出应用 |

#### 共同窗口行为与退出

- 标题栏的收缩/展开按钮负责收缩预览与历史列表之间的切换，不与系统最小化混用。
- 关闭按钮退出应用并停止监听。
- 首期不设计托盘常驻和关闭后继续监听，避免不可感知的后台采集。

### 5.3 单条详情结构

详情项沿用原型布局：

1. 类型行：图标、类型标签、复制时间、收起按钮。
2. 内容区：按类型显示完整内容或受控预览。
3. 元数据行：格式、行数、字符数、尺寸、大小或文件数量。
4. 操作栏：复制、纯文本复制、删除。

操作规则：

- `复制`：按原始类型重新写入系统剪贴板。
- `纯文本复制`：只对文本、链接、JSON、Markdown、代码显示；移除富文本格式后写入 Unicode 文本。
- `删除`：调用 Windows `DeleteItemFromHistory` 删除系统历史项；删除后按刷新结果选择相邻记录。
- 重新复制历史记录时调用 Windows `SetHistoryItemAsContent`，随后按系统返回顺序刷新列表。

### 5.4 25 条记录规则

- `Clipboard::GetHistoryItemsAsync()` 是唯一历史数据源，应用最多展示系统返回的前 25 条。
- 新增、去重和淘汰规则完全由 Windows 管理，应用不自行推断或维护。
- 首期不提供记录级固定能力，也不为记录增加替代性的收藏或置顶状态；置顶只表示应用窗口位于其他窗口之上。
- 应用重启时清空内存中的视图模型，然后重新读取 Windows 当前历史。
- 应用不会在启动或退出时调用 `ClearHistory`，避免无提示地删除用户的系统历史。
- 用户主动点击清空后，确认操作并调用 Windows `Clipboard::ClearHistory()`。

## 6. 内容识别与解析

### 6.1 识别顺序

首期只采用可验证的剪贴板格式和明确文本规则，不做宽泛猜测。识别顺序如下：

1. `CF_HDROP`：文件或文件列表。
2. PNG、DIBV5、Bitmap：图片。
3. HTML 中只有一个明确的 `<a href>`：链接。
4. HTML 中存在 `<pre>` 或 `<code>`：通用代码。
5. 完整文本可被 JSON 解析器解析，且根节点为对象或数组：JSON。
6. 完整文本是绝对 `http` 或 `https` 地址：链接。
7. 文本包含明确 Markdown 结构：Markdown。
8. 其他 Unicode 文本：普通文本。

Markdown 的明确结构限定为以下任意一种：ATX 标题、围栏代码块、连续列表项或引用块。单个星号、短横线或井号不作为识别依据。

无法确定语言的代码统一标记为“代码”，仅使用等宽字体和基础标点着色，不猜测语言类型。

### 6.2 解析失败

- JSON 解析失败后按 Markdown 或普通文本继续识别，不显示“损坏 JSON”。
- 无法生成图片缩略图时，保留记录并显示通用图片占位图。
- 文件路径失效时保留记录，标记“文件不可用”，禁用复制按钮。
- 链接不请求网页标题、图标或 Open Graph 信息；只有剪贴板 HTML 自带锚文本时才显示标题。

## 7. 技术方案

### 7.1 技术选型

为优先满足常驻内存小于 50 MB 的目标，首选：

- C++20 + Win32 原生窗口。
- Direct2D 绘制界面，DirectWrite 绘制文本。
- Windows Imaging Component 读取图片并生成缩略图。
- DWM System Backdrop 实现 Windows 11 玻璃效果。
- Windows 10 使用不透明度更高的纯色/模糊背景降级。
- C++/WinRT `Windows.ApplicationModel.DataTransfer.Clipboard` API 读取、监听和操作系统历史。

不采用 Electron、WebView2、Tauri 或 WinUI 3 作为首期 UI 宿主，原因是它们的基础运行时和多进程开销会显著增加小于 50 MB 的实现风险。

### 7.2 模块边界

| 模块 | 职责 | 主要依赖 |
| --- | --- | --- |
| WindowHost | 创建无边框顶层窗口、DPI、置顶和状态切换 | Win32、DWM |
| ClipboardHistoryService | 调用 Windows 历史 API、监听 `HistoryChanged`、执行复制/删除/清空 | C++/WinRT |
| ContentClassifier | 按固定优先级识别内容类型 | JSON 解析器、轻量文本规则 |
| PreviewBuilder | 生成文本摘要、图片缩略图和类型元数据 | DirectWrite、WIC |
| Renderer | 绘制收缩预览、历史列表、单条详情和交互状态 | Direct2D、DirectWrite |
| SettingsStore | 保存窗口位置、置顶和视觉设置 | 本地配置文件 |

### 7.3 数据流

```mermaid
flowchart LR
    A["Windows HistoryChanged"] --> B["读取系统历史"]
    B --> C["ContentClassifier 识别类型"]
    C --> D["PreviewBuilder 生成轻量视图模型"]
    D --> E["Renderer 更新收缩预览、历史列表或单条详情"]
    F["用户点击重新复制"] --> G["SetHistoryItemAsContent"]
    G --> A
```

## 8. 数据与接口设计

### 8.1 历史记录模型

```cpp
enum class ContentType {
    Text,
    Json,
    Markdown,
    Code,
    Link,
    Image,
    Files
};

struct ClipboardRecord {
    std::wstring id;
    ContentType type;
    std::chrono::system_clock::time_point createdAt;
    std::wstring previewText;
    std::wstring metadataText;
    winrt::Windows::ApplicationModel::DataTransfer::ClipboardHistoryItem item;
};
```

### 8.2 数据保存

- 只在进程内保存最多 25 个轻量视图模型和对应 `ClipboardHistoryItem` 句柄。
- 剪贴板原始内容、解析结果、文本预览、图片缩略图、文件路径和元数据只在进程内处理，不写入磁盘。
- 不创建数据库、历史文件、磁盘图片缓存、文本载荷文件或其他剪贴板内容临时文件。
- 图片和文件首版只读取用于列表展示的元数据，需要复制时直接使用系统历史项。
- 应用退出时释放全部视图模型；启动时重新调用 `GetHistoryItemsAsync()`。
- 窗口位置等非历史设置可以使用小型配置文件保存，但不得包含剪贴板内容。

### 8.3 去重

- 应用不执行内容哈希和去重。
- 历史顺序与重复项完全以 Windows 返回结果为准。
- 复制、删除或清空后等待 `HistoryChanged`，再重新读取系统历史。

## 9. 性能与资源约束

### 9.1 指标

在 Windows 11 x64、Release 构建、100% DPI 环境下验证：

- 收缩预览、25 条纯文本记录、空闲 5 分钟后，私有工作集不超过 50 MB。
- 空闲 CPU 平均占用低于 0.2%。
- 普通文本复制后 100 ms 内更新摘要。
- 三个状态之间的切换动画在 60 Hz 屏幕上无明显卡顿。
- 25 条历史的滚动过程中不预解码不可见图片。
- 图片只在内存中缓存最大 256 x 256 px 的缩略图；离开可见区域后允许释放位图资源。

### 9.2 大内容策略

- 文本预览只构建需要显示的行，不复制完整字符串用于布局。
- 图片通过 WIC 缩放后再进入 Direct2D，避免长期保存完整解码位图。
- 原始图片由 Windows 历史持有，应用只在可见时请求受控尺寸的预览。
- 列表只渲染可见记录及少量缓冲项。
- 图片解码在工作线程执行，结果仅保存在内存中；UI 线程只接收不可变结果。

图片解码期间允许短时超过 50 MB；操作完成并释放解码资源后应在 5 秒内回落到目标范围。该例外必须通过性能测试记录峰值和回落值。

## 10. 安全与隐私

- 默认不联网，不上传剪贴板内容和使用统计。
- 眼睛图标用于暂停/恢复监听；暂停后不读取新的剪贴板数据。
- 窗口和设置中明确显示监听状态。
- 不记录源窗口标题、进程路径或用户账户信息。
- 应用不把剪贴板内容写入磁盘。
- 清空操作会删除 Windows 系统剪贴板历史，执行前必须明确确认。
- 首期不尝试自动判断密码或令牌，避免错误分类造成虚假的安全承诺。
- 用户复制敏感内容前可暂停监听；后续版本再增加应用排除列表。

## 11. 错误处理与边界情况

- Windows 历史关闭：显示启用提示，不创建应用自己的替代历史。
- Windows 历史访问被拒绝：显示策略限制状态，不重复弹窗。
- 剪贴板同时包含多个格式：严格按照识别优先级选择主类型，同时保存重新复制所需的主格式。
- 复制多个文件：摘要展示第一个文件和 `+N`，重新复制时恢复完整路径列表。
- 文件已移动或删除：记录保留但显示失效状态，不尝试寻找同名文件。
- 超长文本：从 Windows 历史项按需读取并仅在内存中处理；预览和列表布局只构建受控片段，详情按可见范围布局。
- 透明效果不可用：回退为高对比度半透明或纯色背景，不影响功能。
- 多显示器：窗口位置按显示器工作区保存；显示器移除后将窗口恢复到主显示器可见范围。
- 高 DPI 切换：处理 `WM_DPICHANGED`，重新计算尺寸和位图缩略图。

## 12. 测试说明

### 12.1 功能测试

- 验证七种展示类型及其收缩预览摘要。
- 验证收缩预览只展示当前记录。
- 验证历史列表最多 25 条且所有记录默认保持紧凑摘要。
- 验证单条详情在列表内原位展开，且同一时间只展开一条。
- 验证收缩预览、历史列表、单条详情之间的全部切换路径。
- 验证最多展示 Windows 返回的 25 条记录。
- 验证重新复制后按 Windows 历史顺序刷新。
- 验证原始复制和纯文本复制的差异。
- 验证应用重启不保留历史投影，并重新读取 Windows 当前历史。
- 验证暂停监听、删除、清空和退出。

### 12.2 格式测试

- 合法及非法 JSON。
- 标题、列表、引用、围栏代码等 Markdown 结构。
- 纯 URL、带锚文本的 HTML 链接和普通含 URL 文本。
- HTML `<pre>` / `<code>` 与普通富文本。
- PNG、DIBV5、透明图片和超大图片。
- 单文件、多文件、中文路径、长路径和失效路径。

### 12.3 性能测试

- 0、3、25 条文本历史下的私有工作集。
- 25 条图片历史下的空闲内存和滚动峰值。
- 连续快速复制 100 次时的稳定性、去重和 UI 响应。
- 运行 8 小时后的内存增长趋势。
- 100%、150%、200% DPI 与双显示器切换。

### 12.4 安全测试

- 验证应用目录不存在历史载荷或图片缓存。
- 暂停状态下不产生新记录。
- 应用不发起任何非用户触发的网络连接。

## 13. 发布与回滚

- 首期提供 Windows x64 安装包和便携包。
- 首次启动默认采用窗口级置顶和收缩预览，直接读取 Windows 当前历史。
- 升级时只保留窗口设置，不迁移剪贴板内容。
- 卸载时不处理 Windows 剪贴板历史，只删除应用设置。

## 14. 已确认设计决策

1. 产品采用收缩预览、历史列表、单条详情三个互斥界面状态，不再使用“展开态”统称后两个状态。
2. 收缩预览只展示当前记录的类型、缩略内容、解析信息和快速复制入口。
3. 历史列表最多展示 Windows 返回的前 25 条记录；列表项默认保持紧凑，不自动展开当前记录。
4. 单条详情在历史列表内原位展开选中记录，同时最多展开一条；收起详情后返回历史列表。
5. 历史列表和单条详情共用大窗口尺寸、标题栏、底部状态栏和滚动容器。
6. 应用不提供记录级固定、收藏或记录置顶；只保留窗口级始终置顶。
7. Windows Clipboard History API 是唯一历史数据源；应用不建立应用侧历史库，也不自行去重或淘汰记录。
8. 剪贴板原始内容及其派生的预览、解析结果、缩略图、文件路径和元数据只在进程内处理，不写入磁盘。
9. 应用可以持久化窗口位置、窗口级置顶等非剪贴板设置，但配置中不得包含任何剪贴板内容。
10. 关闭按钮直接退出应用并停止监听；首期不托盘驻留，也不在后台继续采集。

## 15. 后续决策

- 是否在首期同时支持 Windows 10，还是只保证 Windows 11 的完整玻璃效果。
- 是否增加全局快捷键，用于临时显示/隐藏浮贴。
- 是否增加按进程排除监听，以降低密码管理器和远程桌面场景的隐私风险。
- ARM64 版本放在首期还是后续发布。
